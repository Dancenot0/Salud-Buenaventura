Fundamentos

Los diez principios

Orden de precedencia: en caso de conflicto, el principio de menor número gana.

01 · Claridad antes que decoración

La interfaz existe para que un ciudadano encuentre un servicio. Ningún efecto puede estorbar ese objetivo.

02 · Un solo protagonista por pantalla

Cada vista tiene una acción principal (buscar, llamar, consultar). Todo lo demás es soporte.

03 · Vidrio con jerarquía, nunca decorativo

Tres niveles de glassmorphism con propósito: chrome, superficie y velo. Nunca vidrio sobre vidrio.

04 · Un hueco de marca

Azul-Pacífico como única familia cromática de marca. El color se gasta solo en significado: estados, acciones y énfasis.

05 · Profundidad sutil, no dramática

Sombras multicapa al 4–10 % de opacidad, tintadas al hueco de marca. Nada de bordes negros ni halos intensos.

06 · Movimiento con causa

Toda animación explica un cambio de estado o guía la atención. Duraciones ≤ 700 ms y respeto absoluto a prefers-reduced-motion.

07 · Datos vivos

Estados calculados en tiempo real (abierto/cerrado), no texto estático. La confianza se gana con precisión.

08 · Ligereza radical

Cero frameworks, cero fuentes externas, cero peticiones de terceros. Funciona en un gama baja con conectividad irregular.

09 · Accesibilidad innegociable

WCAG 2.2 AA: contraste, foco visible, semántica, live regions y tamaño de toque ≥ 44 px.

10 · Honestidad del dato

Cada ficha declara su origen, estado de verificación y fecha. Un dato viejo señalado es mejor que un dato falso.

Identidad

Color

Paleta Azul-Pacífico: evoca el océano y la confianza institucional sanitaria. Un acento arena de uso esporádico y semánticos estrictos para estados. Todos los pares texto/fondo cumplen contraste AA (verificados en §10).

Regla del 60-30-10 60 % neutros (fondos y superficies), 30 % tinta (texto), 10 % color de marca y semánticos. Si una pantalla se siente «de colores», sobra marca.

Lenguaje visual

Glassmorphism de tres niveles

El vidrio comunica jerarquía, no decoración. Cada nivel tiene una receta fija: translucidez, blur + saturación, borde blanco y highlight especular superior. Solo funciona sobre el fondo ambiental por capas — nunca sobre otro vidrio.

Nivel 1 · Chromeblur(22px) saturate(185%) · navbar y barras sticky · fondo al 66–82 %.
Nivel 2 · Superficieblur(18px) saturate(170%) · tarjetas, paneles y modales · fondo al 52–72 %.
Nivel 3 · Veloblur(10px) saturate(140%) · chips, filas y celdas internas · fondo al 42 %.

Receta canónica (CSS)

/* Superficie de vidrio · nivel tarjeta */
.glass {
  background: linear-gradient(158deg, rgba(255,255,255,.72), rgba(255,255,255,.52));
  backdrop-filter: blur(18px) saturate(170%);
  border: 1px solid rgba(255,255,255,.68);
  box-shadow:
    0 1px 2px rgba(10,43,54,.03),      /* contacto  */
    0 8px 20px rgba(10,43,54,.06),     /* cercanía  */
    0 24px 48px rgba(10,43,54,.06),    /* ambiente  */
    inset 0 1px 0 rgba(255,255,255,.85); /* specular */
}

Las cinco leyes del vidrio

  • Saturación ≥ 160 %: sin ella, el blur se ve gris y sucio. La saturación devuelve el color del fondo.
  • Borde siempre blanco translúcido (55–85 %), nunca gris: simula el canto pulido del cristal.
  • Highlight especular: inset 0 1px 0 blanco en el borde superior. Es el 50 % del realismo.
  • Texto siempre sólido: el contenido sobre vidrio usa tinta plena (≥ 4.5:1); jamás texto translúcido sobre vidrio.
  • Presupuesto de blur: máximo 4–6 elementos con backdrop-filter visibles por pantalla; en móvil, el chrome puede degradar a fondo sólido al hacer scroll rápido.

Criterio

Reglas y anti-patrones

Lo que distingue un glassmorphism enterprise de uno genérico.

Sí

  • Fondo ambiental con capas para que el blur tenga algo que revelar.
  • Bordes blancos translúcidos y highlight especular superior.
  • Sombras multicapa tintadas al hueco de marca, 3–10 % de opacidad.
  • Un color de marca; el resto del color es semántico.
  • Movimiento breve con curva única y stagger moderado.
  • Grano al 3–4 % para eliminar banding del blur.
  • Estados reales: hover, focus-visible, active, disabled, vacío y error.

Nunca

  • Neones, glows intensos o degradados multicolor saturados.
  • Vidrio sobre vidrio (jerarquía ilegible y coste de render).
  • Texto de bajo contraste sobre superficies translúcidas.
  • Blur en todos los paneles «porque sí»: el vidrio jerarquiza, no decora.
  • Animaciones decorativas en bucle cerca del contenido de lectura.
  • Radios inconsistentes (mezclar 8/12/24 px sin regla).
  • Dependencias externas: fuentes, iconos o librerías de CDN.

Checklist implementado

  • Skip-link y navegación por teclado completa.
  • :focus-visible con anillo doble (blanco + marca).
  • Landmarks semánticos, jerarquía de encabezados única.
  • aria-live en conteo de resultados y toasts.
  • aria-expanded/aria-controls en acordeones y menú.
  • Iconos aria-hidden; las acciones dicen qué hacen.
  • Objetivos táctiles ≥ 44×44 px; texto base 17 px.
  • prefers-reduced-motion desactiva todo movimiento.
  • Fallback sin backdrop-filter: superficies sólidas.

Ingeniería

Arquitectura del proyecto

HTML semántico + CSS en capas (tokens → base → componentes → páginas) + JavaScript vanilla modular. Sin build obligatorio: se abre con doble clic o cualquier servidor estático.

Flujo de datos

  1. datos.js expone window.SBDataModelo central: ips, servicios, trámites, líneas, rutas y avisos. En producción se sustituye por fetch a una API manteniendo el mismo contrato.
  2. chrome.js hidrata la páginaInyecta header/footer, marca el enlace activo, hidrata iconos estáticos y dispara el evento sb:ready.
  3. El controlador de página escucha sb:readyLee parámetros de URL, filtra SBData y renderiza con SBRender (fichas) o plantillas locales.
  4. El estado vive en la URLq, tipo, zona, serv, urg y ver se sincronizan con history.replaceState: toda vista filtrada es compartible y recargable.
